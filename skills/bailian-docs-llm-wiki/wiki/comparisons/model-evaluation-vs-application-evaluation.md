# 模型评估与应用评估对比

## 概述

阿里云百炼平台提供了两套独立的评测体系：**模型评测**和**应用评测**。两者虽然都以"评测质量、驱动优化"为核心目标，但在评测对象、数据流、评分机制和适用阶段上存在显著差异。本文从多个关键维度进行系统对比，帮助开发者在技术选型时快速判断应使用哪种评测能力，或在何种场景下将两者结合使用。

---

## 核心维度对比

### 基本定位

| 维度 | 模型评测 | 应用评测 |
|------|----------|----------|
| **评测对象** | 单个或多个大语言模型（LLM） | 智能体应用、工作流应用 |
| **核心目标** | 选出最优模型、验证调优效果、预防模型风险 | 评估端到端应用输出质量，持续监控与优化上线效果 |
| **评测粒度** | 模型层——关注模型本身的推理与生成能力 | 应用层——关注模型 + Prompt + 知识库 + 检索链路的综合表现 |
| **可用地域** | 仅中国大陆版（北京地域） | 随百炼平台可用地域提供 |

### 评测方式

| 维度 | 模型评测 | 应用评测 |
|------|----------|----------|
| **自动评测** | 自定义评测（自动评估）、基线评测 | 旧版自动评测（基于知识库）、新版评估器自动评分 |
| **人工评测** | 自定义评测（人工评估），评分员手动打标 | 旧版手动评测（人工打分）、新版标签标注 |
| **基线/回归测试** | 支持——基于预置榜单（C-Eval、CMMLU 等） | 不提供标准化榜单，但支持使用同一评测集反复回归 |
| **归因分析** | 不提供系统化归因 | 旧版自动评测提供 5 类 BadCase 归因（模型理解有误、重排不佳、检索无效、切片不完整、未获取知识） |

### 支持的模型与应用

| 维度 | 模型评测 | 应用评测 |
|------|----------|----------|
| **支持模型** | 通义千问商业版/开源版、通义法睿、第三方模型（abab 等），以及基于上述模型调优后的模型 | 不直接选模型；评测对象为已构建的智能体或工作流应用 |
| **支持应用类型** | 不涉及应用层 | 智能体应用（新旧版均支持）、工作流应用（仅新版支持） |
| **应用发布要求** | 无（直接评测模型） | 旧版自动评测要求应用已发布且已配置知识库；新版评测可关联或不关联应用 |

### 数据集与输入格式

| 维度 | 模型评测 | 应用评测 |
|------|----------|----------|
| **数据来源** | 评测数据集（在线推理）或推理结果集（离线上传） | 手动上传（.xls/.xlsx/.jsonl）、基于知识库自动生成、从应用观测导入 |
| **数据集格式** | 自定义 Prompt + Completion，支持 `${prompt}`、`${completion}`、`${output}` 变量注入 | 旧版：对话分析（xls/xlsx）、知识问答（jsonl）；新版：智能体/工作流模板自动生成或自定义表结构 |
| **版本管理** | 未明确提及 | 支持评测集版本管理，需发布后方可用于评测任务 |

### 评分与评估机制

| 维度 | 模型评测 | 应用评测 |
|------|----------|----------|
| **自动评分方式** | 大模型评估（分类型/数值型）、规则评估（字符串匹配/文本相似度） | 旧版：大模型自动评分（1–5 分制）；新版：LLM 评估器 + Code 评估器 |
| **人工评分方式** | 人工评估（分类型标签） | 旧版：较差/一般/较好三档；新版：分类/布尔值/数字/文本四种标签类型 |
| **裁判模型** | 可选择推理能力强的模型（推荐通义千问3-Max） | 旧版仅支持 qwen-max 和 qwen-plus；新版评估器模型限时免费 |
| **相似度算法** | ROUGE-L、BLEU、Cosine、Fuzzy Match、Accuracy | 无内置相似度算法（通过 Code 评估器可自行实现） |
| **评估器扩展** | 通过评测维度配置，支持 Prompt 模板定制 | 新版支持预置模板、自定义创建、基于历史任务创建，最多添加 10 个评估器 |

### 计费方式

| 维度 | 模型评测 | 应用评测 |
|------|----------|----------|
| **Token 费用** | 参评模型在线推理 + 裁判模型评分均产生 Token 费用；上传推理结果集可节省推理成本 | 调用应用产生的 Token + 评估器 LLM 评分的 Token 按标准计费 |
| **免费额度** | 无特别说明 | 新版评估器模型限时免费 |
| **独占资源** | 未明确说明 | 使用独占资源部署的模型不额外收费 |
| **失败任务** | 未明确说明 | 已完成步骤消耗的 Token 仍计入用量 |

### 典型使用流程

| 阶段 | 模型评测 | 应用评测 |
|------|----------|----------|
| **1. 准备** | 选择模型、配置 System Prompt 和推理参数、准备评测数据集 | 创建评测集（上传/自动生成/导入），发布评测集 |
| **2. 配置** | 选择评测方式（自定义/基线），配置评测维度和裁判模型 | 选择应用、配置评估器和标签 |
| **3. 执行** | 系统自动推理+评分（自动评估），或人工逐条评价（人工评估） | 系统自动运行应用+评估器评分，或人工标注 |
| **4. 分析** | 查看评测结果，对比多模型得分 | 查看报告、BadCase 归因分析、对比多版本/多应用结果 |

## 适用场景建议

### 选择模型评测的场景

- **模型选型阶段**：业务初期需要从多个候选模型中快速筛选出效果最优的基础模型。
- **模型调优后验证**：完成 SFT/LoRA 等调优后，需确认调优模型在特定任务和通用能力上的表现变化。
- **安全合规预审**：上线前需检测模型在政治敏感、歧视偏见等风险维度的表现。
- **标准化对标**：需要基于 C-Eval、CMMLU 等公认基准榜单进行能力评测。
- **NL2SQL / Function Calling 等精确匹配任务**：需要利用字符串匹配、BLEU 等规则评估维度进行精准判定。

### 选择应用评测的场景

- **端到端应用质量评估**：关注的不仅是模型能力，还包括 Prompt 工程、知识库检索、重排序等链路的综合效果。
- **RAG 应用优化**：需要基于知识库自动生成评测集，并对检索链路 BadCase 进行归因定位。
- **工作流应用评测**：评测对象为包含多步骤编排的工作流应用（仅新版支持）。
- **持续集成/持续评测**：知识库更新、Prompt 调整、模型更换后，需要在同一评测集上反复回归验证。
- **人工标注与自动评分结合**：新版标签体系支持分类、布尔值、数字、文本四种类型，满足灵活的人工标注需求。

### 建议组合使用的场景

| 阶段 | 推荐方案 | 说明 |
|------|----------|------|
| 模型选型 | 模型评测 | 用基线评测和自定义评测快速筛选候选模型 |
| 模型调优验证 | 模型评测（基线 + 自定义） | 确保调优不损害通用能力，同时提升目标任务效果 |
| 应用原型验证 | 应用评测 | 将选定模型集成到应用后，评估端到端效果 |
| 应用上线后监控 | 应用评测（新版 + 应用观测） | 从线上数据导入评测集，持续回归 |
| 全链路优化 | 先模型评测 → 再应用评测 | 先确定最优模型，再在应用层优化 Prompt、知识库和检索策略 |
