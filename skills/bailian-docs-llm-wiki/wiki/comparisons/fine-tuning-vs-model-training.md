# 模型微调与模型训练对比

## 概述

在百炼平台上，**模型微调**（Fine-tuning Guide）和**模型训练**（Model Training API）是开发者定制模型时最常接触的两个概念入口。前者侧重于调优策略与方法论指导，帮助开发者理解"何时做、怎么做"；后者侧重于 API 层面的工程实现，解决"如何调用、如何集成"的问题。

本页面旨在帮助开发者厘清两者的定位差异、功能覆盖范围和使用方式，以便在技术选型和开发流程中做出合理决策。

## 核心维度对比

| 维度 | 模型微调（Fine-tuning Guide） | 模型训练（Model Training API） |
|------|------|------|
| **文档定位** | 方法论与最佳实践指南 | API 参考与工程实现指南 |
| **核心关注点** | 何时微调、选择哪种调优方式、数据如何准备 | 如何调用接口、参数如何配置、任务如何管理 |
| **使用方式** | 控制台可视化操作 + API/命令行 | 纯 HTTP API / SDK 编程 |
| **调优方式覆盖** | CPT → SFT → DPO 递进策略详解 | `sft`、`efficient_sft`、`cpt`、`dpo_full`、`dpo_lora`、`compile_asr_phrase` |
| **支持模型范围** | 文本生成、视觉理解、视频生成、语音合成 | 文本生成、视觉理解、视频生成、语音合成、**语音识别热词** |
| **数据格式说明** | 按场景详述（ChatML、DPO 对比对、CPT 纯文本、ZIP 包） | 统一文件管理 API，按 `purpose=fine-tune` 上传 |
| **超参数指导** | 提供推荐值与调参建议 | 提供完整参数列表、类型、取值范围及默认值 |
| **API 端点** | 简要提及流程 | 完整定义：`/api/v1/files`、`/api/v1/fine-tunes` |
| **计费说明** | 提供公式与单价示例 | 提及混合数据计费规则，未列单价 |
| **部署与推理** | 含部署和评估流程指引 | 返回 `finetuned_output` 模型 ID 用于推理 |
| **前置建议** | 推荐先尝试 Prompt Engineering 和 Function Calling | 无（假设已决定进行训练） |

## 输入输出格式对比

| 维度 | 模型微调 | 模型训练 API |
|------|----------|--------------|
| **训练数据输入** | `.jsonl`（ChatML 格式）、ZIP 包（视觉/视频/语音） | 通过 `POST /api/v1/files` 上传，获取 `file_id` |
| **单文件大小限制** | 未明确声明 | 单个文件最大 **1GB**；总配额 5GB / 100 个文件 |
| **任务创建输入** | 控制台表单或 API 请求体 | JSON 请求体：`model` + `training_file_ids` + `hyper_parameters` |
| **任务输出** | 调优后模型，可部署调用 | `job_id`（任务追踪）+ `finetuned_output`（模型 ID） |
| **中间产物** | 提及 Checkpoint 但未详述 | `save_strategy` / `save_steps` / `save_total_limit` 精细控制 |

## 支持模型对比

| 模型类型 | 模型微调覆盖 | 模型训练 API 覆盖 | 差异说明 |
|----------|-------------|-------------------|----------|
| Qwen3 文本生成 | ✅ 详细列出各子模型支持的训练类型 | ✅ 以示例形式列出 | 微调指南信息更详细 |
| Qwen-VL 视觉理解 | ✅ 仅 SFT（全参+高效） | ✅ | 一致 |
| 万相视频生成 | ✅ 仅 SFT-LoRA | ✅ 独立超参数集 | API 文档提供更多参数细节 |
| CosyVoice 语音合成 | ✅ 仅 API 支持 | ✅ 8 个 LM/FM 参数全部必填 | API 文档参数说明更完整 |
| Paraformer 语音识别 | ❌ 未涉及 | ✅ `compile_asr_phrase` 热词管理 | 仅 API 文档覆盖 |

## 计费方式对比

| 计费维度 | 模型微调 | 模型训练 API |
|----------|----------|--------------|
| **计费公式** | （训练 Token + 混合 Token）× 循环次数 × 单价 | 同左，另注明混合数据按标准计费 |
| **付费方式** | 控制台支持模型训练单元（预付费/后付费）+ 按 Token | **仅按 Token 计费**，不支持训练单元 |
| **单价示例** | Qwen3-8B: ¥0.006/千Token；Qwen2.5-72B: ¥0.15/千Token | 未直接列出单价 |

> ⚠️ **关键差异**：通过 API 创建的训练任务**仅支持按 Token 计费**，如需使用模型训练单元（预付费资源包），必须通过控制台创建任务。

## 适用场景建议

### 推荐使用 [[fine-tuning]]（模型微调指南）的场景

- **初次接触模型调优**：需要理解 CPT/SFT/DPO 的区别和递进关系
- **方案选型阶段**：评估是否需要微调，还是 [[prompt-engineering]] 或 [[function-calling]] 即可满足需求
- **数据准备阶段**：了解各模型类型的数据格式要求和质量标准
- **控制台操作优先**：团队中有非研发人员参与调优流程，偏好可视化操作
- **使用预付费资源**：需要通过模型训练单元控制成本

### 推荐使用 [[model-training]]（模型训练 API）的场景

- **自动化流水线集成**：将模型训练嵌入 CI/CD 或 MLOps 流程
- **精细参数控制**：需要配置 Checkpoint 保存策略、LoRA 参数、混合训练等高级选项
- **多任务批量管理**：通过脚本批量创建、监控、管理训练任务
- **语音识别热词**：Paraformer 热词管理仅通过 API/SDK 支持
- **CosyVoice 调优**：语音合成模型仅支持 API 方式发起训练
- **二次调优**：基于已调优模型 ID 进行迭代训练

### 两者结合的推荐流程

```
1. 阅读 [[fine-tuning]] → 确定调优策略（CPT/SFT/DPO）和数据要求
2. 准备训练数据 → 按微调指南的格式说明构建数据集
3. 小规模验证 → 通过控制台快速试跑，验证数据质量
4. 生产集成 → 使用 [[model-training]] API 实现自动化训练流水线
5. 部署上线 → [[model-deployment]] → [[model-evaluation]]
```
