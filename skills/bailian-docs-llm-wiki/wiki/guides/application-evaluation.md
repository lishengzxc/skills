# application evaluation

应用评测是阿里云百炼平台提供的一套系统化评估工具，用于衡量智能体应用和工作流应用的输出质量。平台同时支持自动评测（基于大模型打分）和人工评测（人工标注打分），并提供评测集管理、[[grader]]（评估器）、[[label-management]]（标签）等配套组件，帮助开发者在应用上线前后持续跟踪和优化应用效果。

> **注意**：平台当前存在新旧两版评测体系。旧版包含"自动评测"和"手动评测"入口，新版统一为"评测任务"入口并引入了评估器和标签机制。新版评测任务页面左上角提供 **返回旧版** 按钮可切换。以下内容涵盖两个版本的核心功能。

## 评测模式概览

| 模式 | 适用场景 | 评分方式 | 说明 |
|------|---------|---------|------|
| 自动评测（旧版） | 已发布且配置知识库的智能体应用 | 大模型自动评分（1-5 分） | 支持单应用评测和最多 8 个应用的横向评测 |
| 手动评测（旧版） | 已发布的智能体应用 | 人工标注（较差/一般/较好） | 需手动构建评测集并逐条打标 |
| 评测任务（新版） | 智能体应用、工作流应用、纯人工标注 | 评估器自动评分 + 标签人工标注 | 支持自定义评估器（LLM / Code）和多维度标签 |

详细的自动评测操作流程请参考 [自动评测](../../raw/application-user-guide/application-evaluation/application-auto-evaluation.md)。手动评测流程请参考 [手动评测](../../raw/application-user-guide/application-evaluation/evaluate-manual-application.md)。

## 评测集

评测集是所有评测任务的数据基础。平台支持自动生成和手动上传两种创建方式。

### 旧版评测集类型

| 类型 | 文件格式 | 用途 |
|------|---------|------|
| 对话分析 | `.xls` / `.xlsx`（含 Prompt、Completion、SessionId 字段） | 手动评测，支持单轮和多轮对话 |
| 知识问答 | `.jsonl`（含 query、queryType、referenceAnswer、fineKeywords、coarseKeywords 字段） | 自动评测，大模型自动评分 |

### 新版评测集类型

| 类型 | 说明 |
|------|------|
| 智能体 | 根据智能体应用的出入参形式定义表结构 |
| 工作流 | 根据工作流应用的出入参形式定义表结构 |
| 自定义 | 任意定义表结构，适用于特殊评测场景 |

> **注意**：旧版评测集（对话分析 / 知识问答）与新版评测集（智能体 / 工作流 / 自定义）的类型体系不同，创建后类型不可修改。请根据所使用的评测功能版本选择对应的评测集类型。

评测集均需发布后才能用于评测任务，草稿状态不可使用。新版评测集还支持版本管理，每次发布生成新版本。完整的字段规范和创建流程参见 [评测集](../../raw/application-user-guide/application-evaluation/application-evaluation-dataset.md) 和 [新版评测集](../../raw/application-user-guide/application-evaluation/new-version-of-application-evaluation/new-version-of-evaluation-set.md)。

## 评估器（新版）

[[grader]] 是新版评测体系的核心组件，用于自动评估应用输出质量。支持两种创建方式：

- **LLM 评估器**：通过大模型进行语义理解评分，适用于相关性、幻觉检测等需要语义判断的场景。
- **Code 评估器**：通过 Python 3.10 脚本实现评分逻辑，适用于格式校验、精确匹配等规则明确的场景。
- **基于评测任务创建**：从历史评测任务的人工标注结果中自动学习评估规则，生成 LLM 评估器。

平台还提供通用质量、智能体、文本匹配、文本相似度、格式校验等多类预置评估器模板，可直接使用或基于模板修改。

### 关键配置参数

| 参数 | 说明 |
|------|------|
| 评分范围 | 评估器的打分尺度（如 0-1 或 0-100） |
| 通过阈值 | ≥ 阈值为 Pass，< 阈值为 Fail |
| 参数映射 | 将评估器变量（如 query、response）映射到评测集字段或应用输出 |

每个评测任务最多添加 10 个评估器，建议组合 3-5 个评估器从不同维度评估。

## 标签与人工标注（新版）

[[label-management]] 支持四种标签类型：

| 类型 | 适用场景 | 示例 |
|------|---------|------|
| 分类 | 枚举选择（多选） | 回答质量：较差/一般/较好 |
| 布尔值 | 是/否判断 | 是否存在幻觉 |
| 数字 | 精确打分 | 评分 1-5 分 |
| 文本 | 自由文本备注 | 错误原因说明 |

标签可同时用于评测任务和 [[application-observation]] 的数据标注。评测任务支持"普通模式"和"快速标注"两种标注模式。

## 自动评测流程（旧版）

自动评测针对已发布且配置了知识库的智能体应用，完整流程包含四个阶段：

1. **创建评测任务**：选择应用（1-8 个）和知识库，多应用横向评测要求所有应用至少共享一个知识库。
2. **设置评测集**：可由大模型基于知识库自动生成（支持 2-8 种任务类型），或复用已有评测集。生成模型仅支持 `qwen-max` 和 `qwen-plus`。
3. **配置评测规则**：设置每类型采样数量和评测模型，支持试运行预览。
4. **执行评测**：发起评测并等待完成，完成后可追加应用（总数不超过 8 个）。

### 评分与归因机制

- 评分标准：5 分（正确且优秀）、4 分（正确且良好）、4 分以下（错误，触发归因分析）。
- 总正确率 = 得分 ≥ 4 分的回答数 / 总回答数 × 100%。
- 归因类型包括：模型理解有误、重排不佳、检索无效、切片不完整、未获取知识。

### 前提条件

- 应用必须已发布并配置知识库
- 必须开通 [[application-observation]]（应用观测）并将应用加入观测列表
- 子账号需 `管理员` 或 `应用评测-操作` 权限

## 手动评测流程（旧版）

1. 按模板准备评测集文件（`.xls` / `.xlsx`），包含 Prompt、Completion、SessionId 字段。
2. 在评测集页面上传并发布。
3. 创建评测任务，选择已发布的智能体应用和评测集，选择评测维度（内置或 [[evaluation-metrics]] 自定义模板）。
4. 等待推理完成后逐条打标（较差/一般/较好），完成后提交生成报告。

## 评测任务（新版）

新版评测任务统一管理智能体和工作流应用的评测，核心配置包括：

- **评测集**：选择已发布的评测集及版本
- **应用关联**：可选智能体、工作流或不关联应用（纯人工标注）
- **评估器**：添加自动评分器并配置参数映射
- **标签**：添加人工标注标签

任务创建后配置不可修改。任务详情页提供**数据明细**和**指标统计**两个视图。详见 [评测任务](../../raw/application-user-guide/application-evaluation/new-version-of-application-evaluation/evaluation-task.md)。

## 计费说明

- 自动评测和评测任务中调用大模型产生的 Token 费用正常计费。
- 预估平均消耗为参考值，预估最大消耗为成本硬性上限，实际消耗通常远低于上限。
- 任务失败时，已完成步骤消耗的 Token 仍计入用量。
- 新版评估模型限时免费（以平台实际公告为准）。
- 使用独占资源部署的模型不额外收费。

## 最佳实践

### 建立持续评测机制

以下场景建议触发评测：知识库更新、Prompt 调整、模型更换/升级、检索/重排策略变更、定期回归（每周或每月）。

### 优化闭环

识别 BadCase → 分析归因定位问题 → 实施针对性优化 → 发布新版本再次评测 → 对比结果确认改进。

### 评估器组合建议

- 相关性评估器（LLM）+ 格式校验评估器（Code）
- 正确性评估器（LLM）+ 字符串匹配评估器（Code）
- 智能体工具调用评估器（LLM）+ 参数检查评估器（Code）

## 限制与注意事项

| 限制项 | 说明 |
|--------|------|
| 自动评测支持模型 | 仅 `qwen-max` 和 `qwen-plus` |
| 横向评测应用数上限 | 最多 8 个 |
| 评测集文件大小 | 单文件 ≤ 20MB，单次最多 10 个文件 |
| 评估器数量上限 | 每个评测任务最多 10 个 |
| 标签分类选项上限 | 每个分类标签最多 20 个选项 |
| 评测期间禁止关闭应用观测 | 否则可能导致任务失败或数据丢失 |
| 评测任务创建后不可修改 | 如需不同配置需创建新任务 |

## 常见问题

- **评测集生成进度长时间为 0%**：评测为离线排队任务，排队期间进度不更新，开始执行后会自动刷新。
- **评测报告用例数与设置不符**：失败的用例不计入报告，仅显示成功完成的用例。
- **评估器与标签如何配合**：评估器用于自动评分（规则明确的维度），标签用于人工标注（需主观判断的维度），可在同一任务中组合使用。
