# model evaluation introduction

模型评测是阿里云百炼平台提供的功能，允许开发者基于数据集对模型进行多维度评估，以全面了解模型表现并为实际业务应用提供决策依据。该功能支持自定义评测与基线评测两种方式，覆盖人工评估和自动评估场景，适用于模型选型、调优验证和风险预防等需求。

> **注意**：该功能目前仅适用于中国大陆版（北京地域），详见 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md)。

## 为什么需要模型评测

根据 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md) 文档，模型评测主要解决三类问题：

- **模型选型**：从多个候选模型中快速对比表现，选出最适合特定业务需求的模型。
- **调优验证**：在 [[model-fine-tuning]] 迭代过程中，量化检验调优效果并调整后续策略。
- **风险预防**：提前发现模型在政治敏感、违法犯罪、歧视偏见等方面的潜在风险，采取过滤或屏蔽措施。

## 支持的模型

评测功能支持以下预置模型及其调优后的版本（通过 [[model-deployment-introduction]] 部署）：

| 模型系列 | 包含 |
|---------|------|
| 通义千问商业版 | QwQ / Max / Plus / Turbo / Coder / Math |
| 通义千问开源版 | Qwen3、Qwen2.5、Qwen2、Qwen1.5 |
| 通义法睿 | — |
| 第三方文本生成模型 | abab6.5g、abab6.5t 等 |

> **注意**：上述列表可能随时变化，以 [创建评测任务](https://bailian.console.aliyun.com/?tab=model#/efm/model_evaluate/task/creation) 页面中实际显示为准。灰色字体且无"申请"按钮的模型暂不支持评测。

## 评测方式

### 自定义评测

通过自选评测维度，将模型输出与预设答案进行对照来评估表现。支持两种评估模式：

**人工评估**：由评分员（开发者本人或业务专家）根据评测维度对模型输出进行人工评价。优势是可以验证输出内容中每个细节的正确性，劣势是成本高、效率低且存在主观偏差。

**自动评估**：系统基于评测维度和评测集自动评分，无需人工参与。优势是高效且公正，劣势是依赖初始设定的维度和标准。

### 基线评测

基于预置基线评测集（包括 **C-Eval** / **CMMLU** 等主流榜单）自动评测模型的基础通用能力。主要用于 [[model-fine-tuning]] 后的回归测试，确保模型通用能力未因调优而下降。

### 最佳实践

建议将多种评测方式结合使用：先通过人工评估确定评测维度和评分标准 → 应用于自动评估快速筛选候选模型 → 再通过人工评估对比细微差异 → 如有调优则补充基线评测。

## 评测维度类型

根据 [模型评测](../../raw/model-user-guide/model-evaluation-introduction/model-evaluation-overview.md) 文档，评测维度分为以下类型：

### 自动评估维度

| 类型 | 适用场景 | 输出 |
|------|---------|------|
| **大模型评估 - 分类型** | 评测维度明确但难以给出绝对分数的开放任务（如违规检测） | Pass / Fail（通过标签映射） |
| **大模型评估 - 数值型** | 客观评分任务，由大模型按预设维度打分 | 数值评分，根据阈值判定 Pass / Fail |
| **规则评估 - 字符串匹配** | Function Calling 精准度、NL2SQL 等固定答案场景 | Pass / Fail |
| **规则评估 - 文本相似度** | 文本摘要、机器翻译、多模态理解 | 相似度分数（0-1），根据阈值判定 |

**字符串匹配支持的规则**：相等、不相等、包含、开头包含、结尾包含（均忽略大小写）。

**文本相似度支持的算法**：

| 算法 | 特点 | 最佳场景 |
|------|------|---------|
| ROUGE-L | 基于最长公共子序列 | 文本摘要 |
| BLEU | 基于 n-gram 精确匹配 | 机器翻译 |
| Cosine | 向量空间语义相似度 | 开放问答 |
| Fuzzy Match | 基于编辑距离，容错性强 | OCR / 语音识别 |
| Accuracy | 完全匹配 | 精确答案验证 |

### 人工评估维度

**人工评估 - 分类型**：评分员对每条样本手动打标签（如"优秀""良好""较差"），适合评价创意性、幽默感等难以自动量化的主观能力。标签最终映射为 Pass / Fail。

## 关键配置参数

创建自定义评测任务时需配置：

- **评测模型**：选择参评模型，设置 System Prompt 及推理参数（`top_p`、`temperature` 等），参数说明参见 [[qwen-api-reference]]
- **数据来源**：
  - **评测数据集**：模型基于该数据集执行在线推理后由评分器评分
  - **推理结果集**：直接上传模型输出，跳过在线推理，降低推理成本
- **评测维度**：选择或创建评测维度模板
- **裁判模型**（自动评估时）：推荐选择推理能力强的模型（如通义千问3-Max）

## 评测流程

```
创建评测任务 → 执行评测任务 → 查看评测结果
```

- **创建阶段**：设定评测维度、选择评测集（建议使用线上真实业务数据或通过 [[data-processing]] 模拟生成）
- **执行阶段**：人工评估需评分员手动评价；自动评估和基线评测由系统自动执行
- **结果阶段**：评测结果为后续数据驱动决策和模型优化提供方向

## 注意事项

- 调优后的模型若未在评测列表中出现，可能需要先完成 [[model-deployment-introduction]] 部署
- 大模型评估维度中，Prompt 支持 `${[[prompt|prompt]]}`、`${completion}`、`${output}` 三个变量注入
- 建议定期人工抽查自动评估结果，确保裁判模型的评分准确性
- 多名评分员参与人工评估时，应独立标注相同样本并验证评分一致性
